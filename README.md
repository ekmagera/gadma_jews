# GADMA2: демографические гипотезы A–G–M

Воспроизводимый конвейер для сравнения четырёх гипотез родства ашкеназских (A), грузинских (G) и горских (M) евреев по данным WGS/VCF/BCF.

## Гипотезы

- `S0`: одновременное разделение трёх ветвей (политомия; нулевая внутренняя ветвь).
- `T1 A|(G,M)`: ашкеназы отделяются первыми.
- `T2 G|(A,M)`: грузинские евреи отделяются первыми.
- `T3 M|(A,G)`: горские евреи отделяются первыми.

Все модели допускают симметричный обмен генами между каждой парой современных популяций. Последовательные модели также допускают обмен между первой отделившейся ветвью и предковой ветвью двух остальных популяций. `S0` вложена в последовательные модели при длине внутренней ветви, стремящейся к нулю.

## Что делает pipeline

1. Строго проверяет уникальность ID и наличие каждого образца из `metadata/samples.csv` в BCF.
2. Автоматически распознаёт `1`–`22` или `chr1`–`chr22` и оставляет только аутосомные двухаллельные SNP; фильтрует пропуски и MAC. Если в BCF есть только `GT`, фильтры по GQ/DP неприменимы.
3. Делает LD-pruning и выбирает неродственных образцов алгоритмом KING (`kinship > 0.0884`, примерно до второй степени родства).
4. Строит preview и folded 3D-SFS через easySFS в одинаковом режиме `-a`, используя все прошедшие фильтры аутосомные SNP. Folded выбран намеренно: без надёжной анцестральной аллели разворачивать SFS нельзя.
5. Запускает четыре custom-модели GADMA2 (`moments`) с повторными оптимизациями.

## Двухэтапный анализ

1. `select` сравнивает четыре общие топологии S0/T1/T2/T3 по AIC. В каждой модели GADMA оптимизирует все её свободные размеры популяций, времена и миграции из независимых стартов.
2. `refine` запускает больше независимых оптимизаций только для победившей топологии.
3. `scale` применяет несколько литературных сценариев mutation rate и generation time к уже оптимизированной модели. Эти величины не меняют likelihood/AIC; callable sequence length задаётся по маске конкретных данных.

Границы параметров заданы явно в `gadma.bounds`. Если хотя бы одна модель достигает границы, `winner.txt` получает значение `BOUNDARY_REVIEW`: границы надо пересмотреть и повторить `select` для **всех** топологий, иначе их AIC несопоставимы.

Полная инструкция исполнителю, перечень входных файлов и состав возвращаемого архива находятся в [docs/HANDOFF_RU.md](docs/HANDOFF_RU.md).

## Запуск на лабораторном компьютере

### Вариант Docker (рекомендуется)

Нужно установить только Docker и Git. После клонирования, копирования BCF и замены metadata:

```bash
docker build -t jews-demography:latest .
cp /path/to/jews.bcf raw/jews.bcf
bash run_docker.sh preview 8
# вручную записать выбранные проекции в config/config.yaml
bash run_docker.sh sfs 8
bash run_docker.sh smoke 4
bash run_docker.sh select 8
bash run_docker.sh refine
# заполнить sequence_length в config/scaling_scenarios.yaml
bash run_docker.sh scale
bash run_docker.sh pack
```

Все программы устанавливаются внутри образа; результаты появляются в `results/`. BCF не включается в образ. Launcher сначала пробует обычный Docker, а при отсутствии доступа — `sudo docker`. Сам `bash run_docker.sh ...` через `sudo` запускать не нужно.

Встроенного wall-clock лимита нет: каждый повтор GADMA заканчивается по критерию сходимости, а весь этап — после заданного числа повторов. Ограничение по часам возможно только снаружи (например, walltime Slurm или `timeout`); при таком прерывании незаконченная модель при следующем запуске начинается заново.

Нативный launcher оставлен только для разработки. Передача исполнителю и воспроизводимый производственный запуск рассчитаны на Docker.

BCF намеренно не хранится в Git. Таблицу `metadata/samples.csv` необходимо заменить метаданными анализируемого набора; прочие группы не должны смешиваться с A/G/M.

## Перед полным запуском

Сначала выполните до preview:

```bash
bash run_docker.sh preview 8
cat results/sfs/preview.txt
```

Preview является отдельным диагностическим этапом и не запускается автоматически при построении SFS. После каждого изменения данных или QC вручную проверьте его результат и запишите выбранные значения в `projections` файла `config/config.yaml`. Текущие значения `[74, 24, 88]` выбраны по аутосомному preview с `-a` для 41/13/48 неродственных образцов: это максимумы числа сегрегирующих сайтов перед падением кривых A, G и M.

После ручного выбора проекций постройте SFS. Preview автоматически не пересчитывается:

```bash
bash run_docker.sh sfs 8
```

Для перевода оценок в годы и абсолютные размеры заполните `config/scaling_scenarios.yaml`. `sequence_length` — число реально callable нейтральных аутосомных оснований после масок, а не число SNP и не полный размер референса. Для чувствительности к длине отдельный сценарий может переопределить `sequence_length`. Масштабирование выполняется после refinement и не перезапускает likelihood-оптимизацию.

После фильтрации файл `results/qc/autosomes.variant_counts.tsv` должен содержать только 22 аутосомы. Его необходимо проверить до интерпретации SFS и результатов GADMA.

## Сравнение моделей

Основные результаты находятся в `results/gadma/{S0,T1,T2,T3}/`. Сравнивайте максимальный log-likelihood и AIC (`2k - 2logL`); число свободных параметров: 7 для S0 и 9 для T1–T3. Для связанных WGS-SNP обычный AIC формально оптимистичен. Для публикационного вывода добавьте блочный bootstrap по независимым геномным блокам и используйте CLAIC, как в model-selection tutorial воркшопа GADMA.

## Важные ограничения

- Фильтр глубины 8–60 — стартовая настройка, а не универсальная истина; проверьте распределение DP.
- HWE-фильтр намеренно не применён до разделения по популяциям: общий HWE-тест на структурированной выборке создаёт эффект Валунда.
- KING выбирает максимально большую неродственную подвыборку, но список удалённых образцов следует проверить вместе с метаданными качества/покрытия.
- Половые хромосомы исключаются автоматически. Для WGS всё равно желательно применить callable BED-маску, исключающую повторы, low-complexity и плохо маппируемые участки; без неё нельзя корректно задать `sequence_length`.

Основа: [воркшопы GADMA](https://github.com/noscode/GADMA_workshops), включая easySFS, custom models и сравнение AIC/CLAIC.

## Подготовка метаданных

В `metadata/samples.csv` оставлены только три группы, заданные гипотезами: Ashkenazi, Georgian и Mountain Jews (41/14/48 образцов в исходной таблице). Bukharan, Kurdistan, No Tag и Unknown исключены до анализа и не должны попадать в SFS.

Перед публикацией результатов проверьте, что согласие на использование геномных данных допускает передачу производных SFS и метаданных в открытый репозиторий. Сам BCF намеренно не включён в Git.
