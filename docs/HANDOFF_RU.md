# Инструкция исполнителю: демографический анализ A–G–M

## Цель и порядок анализа

Workflow разделён на две статистические стадии и отдельное физическое масштабирование:

1. **Выбор топологии (`select`)** — одинаково обрабатываются S0, T1, T2 и T3; модели сравниваются по AIC на одном и том же folded SFS.
2. **Углублённая оптимизация (`refine`)** — только выбранная топология получает больше независимых запусков GADMA. Каждый запуск заново оптимизирует все свободные размеры популяций, времена и миграции этой модели.
3. **Sensitivity-анализ (`scale`)** — готовая модель пересчитывается в годы и абсолютные размеры для нескольких значений скорости мутаций, времени поколения и callable sequence length. Эти величины не меняют likelihood, AIC и победившую топологию.

## Что нужно получить до запуска

- BCF с генотипами всех доступных образцов; файл поместить как `raw/jews.bcf` либо изменить `input_bcf` в `config/config.yaml`.
- Таблица `metadata/samples.csv` в UTF-8 с колонками `ID,Population`. ID должны точно совпадать с BCF. Допустимые группы: `Ashkenazi Jews`, `Georgian Jews`, `Mountain Jews`.
- Название сборки референса. Workflow принимает хромосомы `1`–`22` или `chr1`–`chr22` и исключает остальные.
- Описание variant calling и предшествующей фильтрации. Если BCF содержит только `GT`, фильтры по `DP` и `GQ` применить невозможно.
- Callable/accessible BED-маска нейтральных аутосомных участков либо рассчитанное число callable оснований. Оно необходимо для абсолютного масштабирования и не равно числу SNP или полному размеру референса.
- По возможности pedigree/список родственников и список образцов низкого качества для сверки с KING.

Не помещать BCF, VCF, PLINK-файлы или индивидуальные генотипы в GitHub.

## Установка

```bash
git clone https://github.com/ekmagera/gadma_jews
cd gadma_jews
docker build -t jews-demography:latest .
mkdir -p raw
cp /path/to/input.bcf raw/jews.bcf
```

Если Docker доступен только через `sudo`, launcher сам попробует `sudo docker`. Команду `bash run_docker.sh ...` запускать от своего пользователя, не через `sudo`.

## 1. QC и ручной выбор проекций

```bash
bash run_docker.sh preview 8
cat results/qc/metadata_validation.txt
cat results/qc/autosomes.variant_counts.tsv
cat results/sfs/preview.txt
```

Проверить 22 аутосомы, состав выборок после KING и порядок популяций `A, G, M`. Выбрать проекции по максимуму/плато числа сегрегирующих сайтов и записать их в `config/config.yaml` в порядке `A, G, M`.

```bash
bash run_docker.sh sfs 8
head -n 1 results/sfs/dadi/A-G-M.sfs
```

Размерности SFS должны быть равны `projection + 1`.

## 2. Быстрый технический тест

```bash
bash run_docker.sh smoke 4
cat results/smoke/model_evaluation.tsv
```

Это проверка чтения SFS и функций моделей, а не оптимизация и не биологический результат.

## 3. Выбор общей топологии

```bash
bash run_docker.sh select 8
column -t -s $'\t' results/model_selection/aic.tsv
cat results/model_selection/winner.txt
```

Число запусков задаётся `gadma.selection_repeats`. Проверить `status`, `completed_repeats`, `log_likelihood_range` и `boundary_warning`. Победителя нельзя считать устойчивым, если повторы не завершились, likelihood сильно расходятся или параметры достигают границ. Два формально проверяемых блокера — незавершённые повторы и границы — дают в `winner.txt` значения `INCOMPLETE` или `BOUNDARY_REVIEW`, и автоматический `refine` останавливается. Большой разброс likelihood требует ручной оценки и, как правило, дополнительных repeats.

Границы размеров, времён и миграций явно заданы в `gadma.bounds` файла `config/config.yaml`. Если граница достигнута, изменить её и повторить `select` для **всех четырёх моделей**. Расширить пространство только для предварительного победителя и продолжать сравнивать старые AIC нельзя.

## 4. Углублённая оптимизация победителя

```bash
bash run_docker.sh refine
MODEL=$(tr -d '[:space:]' < results/model_selection/winner.txt)
tail -n 50 "results/refinement/$MODEL/GADMA.log"
```

Или явно:

```bash
bash run_docker.sh refine T2 4
```

Число запусков задаётся `gadma.refinement_repeats` и по умолчанию больше, чем при выборе топологии.

Явное указание модели предназначено для осознанного повторного запуска, а не для обхода `INCOMPLETE`/`BOUNDARY_REVIEW`. После refinement снова проверить сообщения о границах и разброс log-likelihood между repeats.

## 5. Физическое масштабирование

Вписать callable neutral autosomal length в `config/scaling_scenarios.yaml`, затем:

```bash
bash run_docker.sh scale
```

Результат: `results/scaling/<MODEL>.tsv`.

Если нужно проверить неопределённость самой длины, добавить несколько сценариев со своим полем `sequence_length`. Это меняет абсолютные `Nref`, `Ne` и даты, но не likelihood/AIC. Значения μ, времени поколения и длины не являются новыми оптимизациями GADMA: при multinomial SFS они только масштабируют один и тот же fitted model.

Литературные ориентиры:

- `1.20e-8` мутаций на основание за поколение — Kong et al., 2012, Nature, DOI [10.1038/nature11396](https://doi.org/10.1038/nature11396);
- диапазон `1.10e-8`–`1.30e-8` используется как sensitivity-интервал около прямой pedigree-оценки; Chong et al., 2012 получили `1.20e-8`, 95% CI `0.89e-8`–`1.43e-8`, DOI [10.1038/ng.2418](https://doi.org/10.1038/ng.2418);
- `28.1` года и диапазон `26`–`30` лет на поколение — Moorjani et al., 2016, PNAS, DOI [10.1073/pnas.1514696113](https://doi.org/10.1073/pnas.1514696113).

Это сценарии систематической неопределённости, а не доверительные интервалы модели.

## Чем ограничен расчёт

В workflow **нет встроенного ограничения по часам**. Docker и Snakemake работают до завершения GADMA либо до остановки пользователем/планировщиком. GADMA завершает отдельный генетический поиск по критерию сходимости, а не после фиксированного количества часов.

Нагрузка ограничивается:

- `selection_repeats` и `refinement_repeats`;
- `gadma.processes` внутри одной модели;
- аргументом `cores` для Snakemake;
- внутренними критериями остановки глобального и локального оптимизаторов GADMA;
- внешним walltime Slurm/другого планировщика, если он используется.

Время зависит от проекций и размера 3D-SFS, повторов и процессора. Один repeat не распараллеливается; `gadma.processes` запускает несколько repeats параллельно, а Snakemake распределяет одновременно запускаемые модели в пределах `cores`. Для полного 3D-SFS разумно заранее резервировать дни, но фактическое время надо оценить по screening-запуску на том же компьютере.

Прерванный результат остаётся незавершённым. Launcher добавляет `--rerun-incomplete`, но текущий workflow для чистоты сравнения перезапускает незавершённую модель с начала; поэтому внешний walltime должен быть с запасом.

## Что отправить заказчику

```bash
bash run_docker.sh pack
```

Передать `handoff_YYYYMMDD_HHMMSS.tar.gz`. Он содержит инструкцию, commit репозитория, QC, preview, SFS, конфиги, AIC, логи выбора, refinement и scaling, но не содержит BCF/VCF/PLINK и индивидуальных генотипов.

Отдельно сообщить:

- сборку референса;
- источник callable mask и sequence length;
- описание variant calling;
- числа образцов до и после KING по группам;
- CPU, RAM, внешний walltime и факт прерывания;
- ручные исключения образцов или участков.
