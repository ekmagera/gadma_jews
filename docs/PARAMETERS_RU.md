# Как выбирать параметры

## Проекции SFS

Проекции подбираются заново для каждого набора данных после фильтрации и удаления родственников. Команда `bash run_docker.sh sfs 8` сама создаёт preview, выбирает проекции и строит SFS. Результат выбора сохраняется в `results/sfs/selected_projections.tsv`.

В `config/config.yaml` доступны три режима:

- `mode: auto` — рекомендуемый режим. Для каждой популяции выбирается минимальная проекция, при которой остаётся не менее `min_fraction_of_max_sites` от максимального числа сегрегирующих сайтов. Значение `0.99` сохраняет минимум 99% максимума и не задерживает запуск ручным решением.
- `mode: max` — выбирается проекция с абсолютным максимумом числа сегрегирующих сайтов. Она даёт немного больше информации, но увеличивает 3D-SFS и время оптимизации.
- `mode: manual` — используются значения из `manual` в порядке популяций из конфига, сейчас `A,G,M`. Этот режим нужен только для осознанного sensitivity-анализа или заранее зафиксированных проекций.

На тестовом autosomal preview с максимумами `A=74`, `G=24`, `M=88` правило 99% выбирает `A=68`, `G=22`, `M=79`. Число ячеек 3D-SFS уменьшается с 166875 до 126960, примерно на 24%, при сохранении не менее 99% максимального числа сегрегирующих сайтов в каждой популяции. Это вычислительный компромисс, а не универсальная биологическая константа; всегда проверить TSV-отчёт.

Если нужно изменить правило, отредактировать только этот блок:

```yaml
projection_selection:
  mode: auto
  min_fraction_of_max_sites: 0.99
  manual: [74, 24, 88]
```

После изменения повторить `bash run_docker.sh sfs 8`. Snakemake пересоздаст выбор и SFS.

## QC

`max_missing` задаёт максимально допустимую долю пропущенных генотипов на сайте, `min_mac` — минимальное число минорных аллелей. `king_cutoff: 0.0884` удаляет родственников примерно второй степени и ближе. `ld_window_kb`, `ld_step` и `ld_r2` влияют только на набор LD-pruned вариантов для KING; SFS строится по полному отфильтрованному autosomal VCF после отбора неродственных образцов.

В исходном тестовом BCF есть только поле `GT`, поэтому фильтры `GQ` и `DP` применить нельзя. Для нового BCF с `GQ`/`DP` их добавление требует отдельного согласованного изменения workflow, а не только чисел в конфиге.

## GADMA и вычислительные ресурсы

Аргумент после команды — общий лимит ядер Snakemake, например `bash run_docker.sh select 16`. `gadma.processes` — число одновременно выполняемых независимых запусков внутри одной модели. Для предсказуемой работы `cores` должно быть не меньше `gadma.processes`; повышение сверх числа одновременно выполняемых задач не ускоряет один repeat.

`selection_repeats` задаёт число независимых запусков для каждой из S0/T1/T2/T3. Сначала сравнить все модели при одинаковых repeats, границах и SFS. `refinement_repeats` задаёт дополнительные независимые запуски только для победителя. Больше repeats повышает шанс найти хороший оптимум, но почти пропорционально увеличивает суммарную вычислительную работу.

Рекомендуемый технический запуск:

```yaml
selection_repeats: 8
refinement_repeats: 16
processes: 4
```

Если доступны 16 ядер, можно поставить `processes: 8` и запускать `select 16`; сначала проверить RAM и фактическое время. Встроенного лимита по часам нет. Внешний walltime должен иметь запас, потому что незавершённая модель при повторном запуске начинается заново.

Границы `population_size`, `time` и `migration` одинаковы для всех топологий. Если лучший результат достигает границы, расширить её и заново выполнить `select` для всех четырёх моделей. Нельзя расширять пространство только для предварительного победителя и сравнивать новый AIC со старыми.

## Mutation rate, generation time и sequence length

Эти значения задаются в `config/scaling_scenarios.yaml` после выбора и refinement модели. Они переводят безразмерные результаты в абсолютные размеры и годы, но не меняют likelihood, AIC, проекции или выбранную топологию. `sequence_length` — число callable нейтральных аутосомных оснований после маскирования, а не число SNP и не длина всего референса.
